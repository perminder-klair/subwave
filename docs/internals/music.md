# Internals: music library, tagging and the picker

Why the library, tagging and track-selection code is shaped the way it is. The
short invariants are in the root `CLAUDE.md`; read the matching section here
before changing any of them — several record a measured property of a real
library (an 11k-track station) that is not obvious from the code.

Covers: Subsonic ingest, multi-value genres, era-year resolution, the
similarity/embedding text, audio-mood calibration and propagated energy, LLM
provider wiring, the artist-variety guard, seed-vs-pick, dead-air trim,
festivals, listener request hardening, likes, and the blocklist rules.

- **Subsonic**: keep using `getAnnotatedUri` for anything going to Liquidsoap — raw URLs lose metadata until ID3 arrives, and the `on_metadata` hook needs `subsonic_id` for `/cover/:id` artwork.
- **Genres are multi-value**: `subsonic.songGenres(song)` is the single ingest normaliser (OpenSubsonic `genres: [{name}]` array → `string[]`, legacy scalar fallback). library.db stores `genres` as a JSON array; the scalar `genre` column is GENERATED (genres[0], indexable) — write `genres`, never `genre`. Matching is any-of via `show-filter.ts trackGenres/genreMatches`; LLM-facing shapes carry all tags comma-joined in the `genre` field. **Genre matching is one-directional**: a track's tag may REFINE the show's genre (a "Punk" show admits a `Punk Rock` track) but never broaden it (a "Pop Punk" show rejects a plain `Pop` track), and containment is word-boundary aligned so a "Rap" show doesn't pull `Trap`. The reverse direction is what let strict shows leak broad tags — don't reintroduce it. Note the resolver `subsonic.resolveGenreName` is still deliberately loose both ways: it maps free text to a real library tag for listener requests and server-side fetches, so a show whose genre isn't a library tag can still broaden there (see issue for the fetch-hint/match-target split).
- **Era years (#842)**: a track's era is judged by `show-filter.resolveEraYear`, never raw `year` — the resolved `original_year` wins (walk-time album `originalReleaseDate` on non-compilation albums; MusicBrainz phase-0 enrichment for compilation tracks), and a **compilation's plain `year` is untrusted** (it's the compilation's own release date, so unresolved comp tracks read as unknown-year and drop from era windows). SQL-side era filters (`library-db.filter` yearFrom/yearTo, seed decade bucketing) mirror the same precedence — keep JS and SQL in agreement. `music/musicbrainz.ts` is keyless but hard-throttled to 1 req/s with a descriptive User-Agent (MB policy) — don't widen it; misses are stamped (`original_year_checked_at`) so passes never re-query them. **Every listener-facing surface reads the RESOLVED year, never `song.year`** (#1418): the Liquidsoap annotation (`subsonic.getAnnotatedUri`), the DJ's "Now starting:" line (`llm/internal/prompts/scripts.ts` — this is what the station SAYS), the picker's slim projection (`picker/slim.ts`), and `/now-playing` (`routes/public.ts`, which is where the skins' year comes from — `now-playing.json` carries no year of its own, radio.liq writes title/artist/album/id only). Each had read the raw column, so a reissue anthology had the DJ announcing 2012 over a 1964 Stax single even when the era pipeline had resolved it. Unknown means the field is **omitted, not zeroed** — the same "leave it out rather than assert the wrong decade" rule the era filter follows. Admin surfaces (library table, playlist builder) deliberately keep the raw `year`: the operator is looking at the file. Pinned by `scripts/era-year-surfaces.test.ts`. **The lookup gate is era SUSPICION, not Navidrome's flag** (#1418): keying it on `isCompilation` limited the MusicBrainz pass to 27 tracks out of 27,860 on the reported library, because reissue anthologies arrive as `isCompilation: false`. `music/era-suspect.ts` owns the judgement — a policy module, not a branch in the walk, because the same call is now made from the walk, the lookup gate and the era resolver. It is tuned **precision-first, against a real 9,216-track catalogue rather than by reasoning** — reasoning got it badly wrong, and the first cut flagged 24% of that library. Signals: Navidrome's flag; a Various-Artists album artist; a record with **no lead artist at the front of it** (≥5 distinct *lead* artists, ≥8 tracks, top lead under 30%); a title that says it is a collection (short, specific word list); or a date range in the title that CLOSES before the album's year — the single-artist anthology no artist-count signal can see ("The Atco/Atlantic Singles 1968–1974" on a 2015 release). Three measured findings shaped the artist rule and are pinned as tests: **count `artistRootKey`, not the raw `artist` string** (it carries the features, so "Slauson Boy 2" read as 13 artists and "Mr. Morale" as 9 — both single-artist records; this is the single biggest correctness win in the module); a bare "≥3 artists" rule flags ordinary features-heavy albums wholesale; and **small releases break any ratio test**, since a 4-track EP with four collaborators has no dominant artist by arithmetic alone. The tuned rule lands on 5.9% of that catalogue and reads as DJ mixes, soundtracks, label samplers and various-artist collections. **Re-measure before loosening any of the three numbers.** A false positive costs a 1 req/s MusicBrainz call and can drop a good album out of era shows; a false negative just leaves the old behaviour. The walk logs the blast radius by reason. **Three columns, three jobs**: `is_compilation` is the raw Navidrome FACT, `era_untrusted` the derived verdict, and `yearUntrusted` (composed as `is_compilation = 1 OR era_untrusted = 1`, once, in the row mappers) is the ONLY one era resolution reads — `resolveEraYear`'s third argument is that composed value, and `needsOriginalYearLookup` deliberately refuses the raw flag so a call site can't reopen the gap. Both NULL means "not yet re-walked", which reads as pre-#1418 behaviour exactly. Keep the SQL twins in step: `browse.ERA_YEAR_SQL` and `idsNeedingOriginalYear` carry the same OR. **The walk no longer records an uninformative album tag**: `originalYear` is written only when the album is not suspect AND `originalReleaseDate.year !== year` — an echo of the release year carries no information yet made 18,492 rows look resolved and hid them from the lookup, which skips a non-null `original_year`. Migration 21's `clearEchoedAlbumTagYears` does the same to existing rows and is behaviour-neutral by construction (a trusted album falls through to the identical `year`); it spares a `musicbrainz` or `manual` value that merely coincides with the file year, and spares any `album-tag` year that DIFFERS — those carried real reissue information. Pinned by `scripts/era-suspect.test.ts` (pure, negative cases are the point) + `scripts/manual-original-year.test.ts` (real SQLite, including both directions of the migration). **The operator override is the third and highest-precedence source** (`POST /library/original-year`, `db.setManualOriginalYear`, the `original year · era` field in the library row editor): `original_year_source = 'manual'` outranks both `album-tag` and `musicbrainz`, and **both automatic writers must refuse to touch it** — the walk's upsert (`IN ('musicbrainz','manual')`) and `setOriginalYear`'s WHERE clause. That guard is load-bearing rather than tidy: every walk re-visits every track, so an override the walk can clobber is one the next rescan silently undoes. `originalYear: null` CLEARS the override (year + both stamps back to NULL) and returns the track to the automatic pipeline, rather than pinning "unknown" — "I was wrong about this one" has to be recoverable without a library reset. **The clear only touches rows whose source IS `'manual'`**: the route's `applyToAlbum` loop runs it over every album track, and a sibling holding a `'musicbrainz'` or informative `'album-tag'` year was resolved, not overridden — clearing those in one click would read as unknown-year on every listener surface until a manual enrichment pass. The reconcile walk (`--reconcile-only`) stamps `era_untrusted` and clears stale album-tag years like any walk, so it **chains the same MusicBrainz backfill after its prune** (`enrich.backfillOriginalYears`, shared with phase-0) — without it, the reconcile button performed only the destructive half of #1418 and nothing ever scheduled the lookup that re-answers those tracks; the `checked_at` stamp keeps later reconciles incremental. The override deliberately does **not** invalidate the track's embedding: the `Era:` line is stale until the next retag/tag pass, but dropping the vector to force a refresh would pull the track out of similarity search entirely, and one wrong decade word in a blob carrying genre, tags, lyrics and acoustics is a smaller distortion than a hole in the KNN pool. Era FILTERING reads the column and is correct immediately. Pinned by `scripts/manual-original-year.test.ts` (real SQLite — all three writers are SQL CASE expressions, so a pure test would pass on every possible bug here).
- **Similarity signal (#1246)**: `music/embeddings.formatTrackText` is the canonical embed text and carries **head line + Last.fm tags + lyric excerpt + a `Sound:` line of measured acoustics + an `Era:` decade line** (Sound: zero-shot CLAP `audio_moods`, a tempo BAND from bpm, major/minor from the Camelot `musical_key`, and `instrumental` as a MINORITY marker (`vocal_ranges = []` speaks, vocal tracks don't — a word ~80% of a library shares clusters nothing) — words, never raw numbers or codes, which embed as arbitrary tokens; Era: the decade word from `show-filter.resolveEraYear`, never raw `year`, and being label-derived it deliberately does NOT count as musical signal in `labelOnlyVectors`. The pace curve is deliberately NOT embedded — its practical range is ~0.02–0.5 so fixed thresholds stamp one word on everything, and relative ones break determinism; see `TrackAcoustics`). The tagger's own `moods`/`energy` must **never** go in: phases run enrich → embed → seed → propagate, so those are decided AFTER the vectors exist by voting over the KNN graph built FROM them (`tag-library.ts`), and feeding them back is circular — on a fresh library they don't even exist yet. With every optional line empty the vector IS the label, so similarity ranks by artist/album wording while presenting itself to the picker as mood similarity (a prolific artist self-clusters; "Nick Drake" lands next to "Drake") — `library-coverage.labelOnlyVectors` is what makes that visible, and `enrichment.lastfmTags` defaulting to `null` = auto (fetch only with an API key) is the usual reason a library has none. Changing the text shape means bumping `EMBED_TEXT_VERSION` + `embedding_meta.text_format`, a SOFT advisory (`embeddingFormatStale`) that never blocks a tag run the way a model/dim change does; `resolveIndexTextFormat` records the OLDEST shape still in the index, because a forward run leaves existing vectors alone.
- **Tempo timing is octave-safe at consumption (#1417)**: `librosa.beat.beat_track` can return the DOUBLE on slow material; the measured failures were one-directional, with true 62–88 BPM tracks stored at 124–176. Attempts to choose the octave from onset alternation, `start_bpm` voting and tempogram harmonics did not separate real-audio positives from backbeat controls well enough to ship, so the analyser keeps its raw reading and does **not** force a library re-analysis. `music/mix.ts:timingBpm` instead folds readings at or above 110 downward by octaves before any single-track duration is derived. A true fast track remains musically aligned at half-time (every other beat); a genuine slow reading is never multiplied into a half-bar. The fold is shared by adaptive/ending/washout canvases, washout delay, loop length and chop period, while stored/display BPM, playlist filtering and embedding text remain untouched until an estimator is validated against a real corpus. **Every effect period reaches its audible window by HALVING, never by clamping** — the fix's own first cut clamped after folding, and because the clamp bound over the whole 110–160 band it returned a flat 0.75 s chop gate for the commonest tempi in a library (1.38 beats at 110 rising to 1.90 at 152), so the gate walked the grid and cut mid-note; the washout tap collapsed to a flat 0.45 s for every reading from 110 to 200 and stopped being a dotted eighth of anything. A clamped period is a number inside the window that is a subdivision of nothing. Halving also makes `chopPeriodFor`/`washoutDelayFor`/`loopBarFor` octave-invariant **at any tempo**, so they do not depend on the 110 line at all — only the bar-snapped canvases do, which is why a double landing below 110 (a true 52 read as 104) is left alone rather than guessed at. `scripts/mix-fx.test.ts` pins half/double invariance across every timing consumer AND the grid property itself — each period must be a power-of-two multiple of the raw beat, swept over 30–300 BPM. Equality between two readings alone does not pin this: two equally off-grid values compare equal, which is how the clamp regression passed its own invariance test.
- **Audio-mood calibration + propagated energy (#1362)**: CLAP cosines are **not comparable across moods** — each prompt sits at its own baseline in the shared space, so picking "this track's top-scoring moods" off raw cosines ranks PROMPTS, not tracks (measured on an 11k library: `energetic` fired on 61.7% of tracks and `rainy` on 43.5%, against `calm` 0.9% and `spiritual` 0.2% — a property of the vocabulary, not the music). `music/audio-calibration.ts` is the one place that fixes this: per-mood library-wide mean/sd → `z = (score - mean) / sd`, then the SAME relative top-K selection on the z axis (margin in **standard deviations**, `DEFAULT_MARGIN_SD`, not raw cosine — the old 0.05 has no meaning here). Baselines are computed from **every stored score map, library-wide**, never from a subset: a distribution built only from the tracks the tagger found hardest to read is a biased yardstick. Below `MIN_BASELINE_TRACKS` (200) selection falls back to raw and is byte-for-byte the pre-#1362 path — `topAudioMoods` is now a thin wrapper over `selectAudioMoods(scores, null)` and keeps its own unit test. **The floor is applied PER MOOD, by pruning, not by gating the set** (`prunedBaselines`, the one path `loadBaselines`/`runPropagatedEnergyPass` both take): per-mood `n` diverges — a mood added to the vocabulary since the last full re-score is only scored on tracks analysed after it — so an established mood can sit at n=5000 beside a new one at n=12, and gating on the MAXIMUM `n` (the original reading) let the thin one into the baselines, where its near-degenerate sd is restrained only by `MIN_SD` and its z explodes into a mood that wins every track: the exact #1362 failure, one mood at a time. Requiring EVERY mood to clear the floor is the wrong correction in the other direction — one new vocabulary entry would refuse calibration library-wide. Pruning keeps the library calibrated on its established moods and simply omits the thin one, which `centeredScores` already drops rather than passing raw. **A pass that could not calibrate stamps `UNCALIBRATED_VERSION` (0), never the real one** (`moodStateHashFor` — never call `composeMoodStateHash` from a pass): those labels came from the raw fallback, so the relabel is still owed, and stamping them as current is what made a station that started under the floor and grew past it keep its original tracks on raw selection forever while only post-crossing tracks were ever calibrated. 0 is deliberately the same value a legacy bare hash parses as, because it means the same thing. **The pass is three phases and the order is load-bearing**: score → compute baselines → derive labels. Labels cannot be picked during scoring, because on a full re-score the baselines are a property of the cosines being written by that very loop. A crash between phases leaves `audio_moods` NULL, which `idsNeedingAudioMoods` re-picks up, so the split is resumable rather than lossy. **`audio_embedding_meta.mood_vocab_hash` now carries TWO things joined by `:`** — the vocabulary hash and `CALIBRATION_VERSION` — because they invalidate different amounts of work: a vocabulary change means the *cosines* are stale (full CLAP re-score, needs the analyzer text tower), a calibration change means only the *labels* are (re-derive from disk, `relabelFromStoredScores`, no analyzer at all). Folding the version into the vocab hash instead would strand every install that doesn't run `ANALYZER_HEAVY` — which is most of them — on stale labels. A legacy bare hash parses as version 0, so an upgrade relabels rather than re-scoring. Composite string, so no schema migration. **Energy correction** (`music/propagated-energy.ts`): a `source = 'propagated'` energy is inherited from embedding neighbours, not judged from the track (41% of that library), and where the measured arousal axis — mean z of `HIGH_ENERGY_MOODS` minus mean z of `LOW_ENERGY_MOODS` — is decisive, it overrules the guess. **Deliberately two-sided, never a three-way bucketing**: `audioEnergy` returns `high`/`low`/**null**, and the ambiguous middle returning null is the whole design — bucketing it to `'medium'` would replace one guess with another and call it evidence, whereas null leaves the existing value alone, so a mis-tuned threshold costs coverage rather than correctness. Scope is `source = 'propagated'` ONLY (an `llm`/`manual`/`uncertain-llm` energy is a real per-track decision and is never touched), and the write is the `energy` column ALONE — source/confidence/moods stay as propagation left them, so a corrected row still reports honestly that its MOODS are inherited. The mood names couple this to the shipped vocabulary and moods are operator-editable, hence the degradation: whichever names survive are used, and fewer than 2 on either side yields null rather than a one-sided answer. Runs after `runAudioMoodPass` in `analyze.ts` AND at the end of the tagger's phase 3/4 — one shared path, because a library can gain audio scores long after it was tagged. `ENERGY_HIGH_Z`/`ENERGY_LOW_Z` (±0.35) and `DEFAULT_MARGIN_SD` are defensible starting points, **not measured optima** — they want a pass against a real library. Pinned by `scripts/audio-calibration.test.ts` (pure) + `scripts/propagated-energy.test.ts` (real SQLite; every query here is new SQL that pure tests would pass right through). Issue #1362's third proposal — weighting scores inside the strict `moodLock`/`energyLock` — is deliberately NOT done: those locks are hard with no never-starve on the agent path, so a continuous score there changes starvation behaviour on thin shows and needs its own spec.
- **LLM**: calls go through the AI SDK via the `llm/sdk.js` primitives; `matchRequest` + pool picker use `djObject` (Zod-validated, no manual JSON parsing). Default provider is the homelab Ollama box — reliable but maybe slow; **don't add aggressive retry**. Adding a provider: extend `LLM_PROVIDERS` in `settings.js`, add a builder case in `llm/internal/provider/registry.ts`, and a descriptor in `llm/internal/provider/capabilities.ts` (thinking knob + object strategy); call sites never name a provider, and per-provider quirks live ONLY in `capabilities.ts`.
- **Back-to-back artist guard** (agent path, #1124/#1187/#1251): the agent's discovery tools deliberately carry no artist filter (#618 — a strip inside the tools gutted the similarity pool on niche catalogues), so variety is enforced at the point of choice. If the pick repeats the on-air artist, `pickViaAgent` re-picks from the run's own other-artist candidates, escalating to a `blockedArtists` pool call when the run surfaced none, and only then allowing the repeat (logged either way). **Which candidates the re-pick may choose from lives only in `broadcast/dj-agent/artist-guard.ts`** — never inline at the call site — and it excludes the artists of the `ARTIST_VARIETY_WINDOW` (5) surrounding slots — queued-and-unaired, on air, and last played (`queue.neighbourArtistRoots`) — as well as the predecessor: an exclusion that remembers only the on-air artist keeps returning to whoever ranks next-highest, which is the same artist every OTHER slot rather than every slot (#1251). Wholly-recent alternatives fall back to the bare exclusion — never starve. Comparison is on `artistRootKey` (`music/recency.ts`), the lead-artist key, so a collaboration can't walk past a guard on the artist fronting it; `artistKey` stays the raw identity key because `trackKey` must keep matching the `title|artist` keys `queue.recentlyPlayed` builds from tag text. Pinned by `scripts/artist-guard.test.ts`.
- **Artist spacing** (agent path, #1406): the guard above only ever fired on the artist ON AIR — the recency window narrowed the re-pick pool but never the entry condition, so a pick three slots after the same artist was never examined and the window never consulted. Reported live as one artist across a whole morning show, every occurrence legal. `artistGuardCause()` (same module) now returns **which** of two causes fired, and they escalate differently on purpose: `'onair'` is a fault and keeps the full #1187 cascade (re-pick → `blockedArtists` pool rescue → relax); `'recent'` is a preference and **yields to the run** — if every alternative is also inside the window, or the constrained re-pick doesn't land, the original pick simply stands. No pool rescue, no second model call chasing spacing, so this can never cost the station a slot or a transition's latency. The window is `settings.llm.artistVarietyWindow` (slots, 0–25, default `ARTIST_VARIETY_WINDOW` = 5; **0 disables spacing only** — back-to-back is not operator-disableable). The composition of those decisions is `runArtistGuard()` in the same module, with the two expensive calls (the constrained re-pick, the pool rescue) INJECTED — `pickViaAgent` keeps every queue and settings read and hands the policy values only. That is what makes the escalation difference testable without a model call; it was previously inline at the call site and verifiable only by reading. Pinned by `scripts/artist-guard-run.test.ts` (every path, counting the injected calls — the spacing cost guarantee IS an assertion that `poolRescue` was never called), `scripts/llm-artist-variety-window.test.ts` (cold-load round trip) and the cause table in `scripts/artist-guard.test.ts`.
- **`artistRootKey` folds verified name variants, not just collaborations** (#1406): a leading article, exact full-name aliases and curly-vs-straight apostrophes. "The Jimi Hendrix Experience" straight into "Jimi Hendrix" walked past the guard because the keys differed, so the known catalogue forms map to one root. Ensemble suffixes are **not stripped generically**: "The Beta Band", "Manchester Orchestra" and "Kronos Quartet" are complete act names, and collapsing them onto Beta/Manchester/Kronos would feed a false equivalence into `blockedArtists`, which `filterPickerCandidates` treats as a hard drop. Add only a verified full-act alias. Normalisation never empties a key ("The Band" → `band`, "The The" → `the`), and article/alias handling runs AFTER the join split so the `X & the Y` exception still sees the tail it protects. Note `queue.recentArtistsSince` is **raw** lowercase, not root keys, and feeds the pool picker's relaxable filter — matched raw against raw, so it does not share this normalisation.
- **Seed vs pick (#1247)**: every pick/request event message hands the agent the ON-AIR track's `[id: …]` so it can seed the discovery tools — and those tools all EXCLUDE the seed from their own results (`library-db/vectors.ts` `knnByBuffer` drops `excludeId`), so that id is the one real, well-formed track id in the model's context that no tool returned. `util/pick-seed.ts` owns the one wording that says so (`SEED_NOT_A_PICK_CLAUSE`, shared by the pick + request schema `id` descriptions AND `picker-tools.ts`'s empty-result `rule`) — never inline a second copy, and don't weaken it to "never invent an id", which an echoed seed literally satisfies. The trigger is upstream: the harness allows exactly ONE discovery call (`COMMIT_AFTER_STEPS = 1`) before pinning `activeTools: ['done']`, so a seed tool that returns nothing corners the model with an empty `seen` — where BOTH salvage stages are structurally dead (`nearestId` has no keys, `repickFromSeen` returns null on its first line). Hence `buildPickerTools`'s cross-index rescue: `tracksLikeThis`/`tracksThatSoundLikeThis` answer from the OTHER index when the one asked holds no vector for this seed (gated on the primary matching *nothing* — an all-filtered-by-recency primary keeps its `emptyResult`), and it says which index answered so the model doesn't reason about audio neighbours on the text axis. A zero-candidate run does NOT count against the agent circuit breaker (`classifyPickFailure`) — it's library coverage, not a model that can't drive tool calls, and opening the breaker there kills the session-aware picker for 10 min while advising "switch model" — but ONLY when at least one real discovery call ran (`toolCalls > 0`; `flattenToolCalls` excludes the synthetic `done`): an empty `seen` with ZERO discovery calls means the model never explored (`no-discovery`), which is exactly the breaker's failure class and still counts.
- **Dead-air trim**: some rips carry seconds of silence before the music starts or after it ends, and on air that plays as dead air. The analyzer measures both edges against an **absolute** dBFS floor (`SILENCE_DBFS`, default -50) as `lead_silence_ms` / `tail_silence_ms` (+ `tail_start_ms`, the same tail measurement as an ABSOLUTE offset — a cue_out derived as `duration - gap` inherits every disagreement between the container tag and the decoded file, so the cut moves by whatever the header got wrong), and `music/silence-trim.ts` turns them into `liq_cue_in` / `liq_cue_out` — `radio.liq`'s existing `cue_cut` (added for the #447 length cap) does the cutting, so no mixer change was needed. **The absolute floor is the whole design.** The two measurements that already looked like the answer — `estimate_intro_ms` and `analyze_outro`'s wind-down — are RELATIVE gates gauged against the track's own loud level, which is the right question for "may the DJ still be talking" and the wrong one here: a quiet piano intro clears neither and is unambiguously music, so reusing them would cut into the record. Never wire a relative gate to a cue point. Three guards bound the damage, each for a different failure: the operator's `silenceTrim.minGapMs` floor (a track legitimately opens a beat after zero, and a segued album's inter-track space is deliberate), a fixed `MARGIN_MS` left in place at each edge (the measurement reports the first frame ABOVE the floor, so cutting exactly there lands on the attack), and a `MAX_TRIM_SEC` ceiling so one bad measurement can't halve a song. **Off by default** — it acts on a measurement, and an upgrade must sound byte-identical until the operator asks for it; `ANALYSIS_VERSION` 7 re-targets the library so the columns fill on the next pass. Three consumers share the module and must not drift: the queue drain, the `auto.m3u` rewrite (`broadcast/scheduler.ts`) and `/now-playing`'s track clock — the last one publishes the PLAYABLE span (`drain-policy.playableDurationSec`), because a tagged duration runs every skin's progress bar past the end of the song by exactly the silence that was cut — the fallback playlist is exactly where a divergent second copy goes unnoticed, because nobody is watching when it plays. **A trimmed head shifts every onset the analyzer measured from byte zero**: `shiftOnsetMs` is applied inside `introMsFor` / `firstVocalMsFor` / `introMsOf`, at `applyPairStamps`, and on the bed's ramp budget in `maybePushBed` — that last one is the same vocal onset `firstVocalMsFor` shifts, and leaving it raw made the two disagree about one track (the prompt told the runway was 2s while the bed decision still thought it was 8s and declined a bed the link needed). The tail moves things too: the ending-aware exit canvas measures its wind-down to the trimmed end, not the tagged one, or it counts the silence being cut as part of the ramp. **Every consumer of the trimmed timeline is a `resolveSilenceTrim` call, never a local subtraction.** Both cue points also fold into the queue clock: the playable span is `[cue_in, min(duration, cue_out)]`, so pair-drain deadlines do not count either the skipped head or the cut tail as runway. The tail is measurable only off a file the analyzer proved COMPLETE (a byte-capped download's "tail" is mid-song), so it follows `outro_json`'s COALESCE write rule; head trim works either way. That proof has two different shapes and they are not interchangeable: for a normal track the seek to `duration-20s` IS the proof (a truncated file cannot reach it, and the short-decode check catches it), but the short-track path decodes from offset ZERO, where a file truncated to 70% decodes 70% and clears the same check — so a short track is measured **only** when the caller's `complete` flag says so. A rendered stem seam vetoes on either trimmed edge (`maybeRenderBlend`), because the clip is mixed FROM the outgoing tail and the incoming head: a trimmed successor head would be baked into the clip and air the very silence the trim removes. Pinned by `scripts/silence-trim.test.ts` (the arithmetic, including a cold-load round trip on the settings key), `scripts/silence-trim-library.test.ts` (**the plumbing** — nothing in production hands the resolver a track object carrying the measurements, so `library.get()`'s hand-written projection IS the feature: a column missing from that field list doesn't degrade the trim, it disables it silently with the analysis sitting in the row), `scripts/drain-policy.test.ts`, and `scripts/analyzer_silence_test.py`.

Fixed month/day schema, so lunar holidays (Easter, Eid, Lunar New Year) shift year-to-year and need per-year entries. `windowDays` spans month/year boundaries (`getFestivalContext` compares real dates).
- **Listener request hardening** (raid 2026-07-28): every on-air safety decision for requests lives in `util/request-guard.ts` (scripted-opener stripping, verbatim-echo guard on intros/acks, requester-name screening), pinned by `scripts/request-guard.test.ts` — never inline a guard in routes or agents. `settings.requests` (enabled / maxPending / cooldownSec / perIpHourlyCap / globalHourlyCap / onePendingPerIp / repeatCooldownMin) drives `POST /request`'s gates and `middleware/ratelimit.ts`, applies live, and coerces to safe defaults when absent; env `REQUESTS_DISABLED` stays the hard override. Conversational messages are classified by an explicit `kind: 'track' | 'chat'` on **both** paths (`matchRequest`'s `REQUEST_SCHEMA_TOLERANT` and the agent's `requestSchema()`), each with `objectFallbacks: { kind: 'track' }` — chat gets an in-persona text ack, nothing queued. The classification must never be inferred from a null `id` alone: `coerceModelPayload` maps an OMITTED key to null, so "the model forgot the field" and "the listener wasn't asking for music" would be the same wire value, and a real request would silently play nothing. An omitted/botched `kind` degrades to `track` and falls through to the repick salvage + stateless cascade. `languageDirective`/`agentLanguageReminder` now ALWAYS render (default English) with a never-switch clause — the empty-when-unset behaviour is what let session-history mimicry flip the station into Russian; do not restore it. Raw request text survives only in the operator request log; the session, prompts, and air see cleaned text.
- **Likes + the operator heart** (#991, #1253): `state/likes.json` (`broadcast/likes.ts`) is accountless — one record per apparent listener per AIRING, keyed `HMAC(persisted secret, ip)`; the raw IP is never stored and one NAT is one key. The **operator's own heart** (the admin library row action) is a real record under the reserved `listenerKey: 'operator'` + `via: 'operator'`, paired with a synthetic `${songId}|operator` airing key so the existing dedup makes it idempotent per song. It counts in `countForSong` and reaches the picker like any like — the `via` marker exists so surfaces can tell them apart, not so one is second-class. Two exemptions are load-bearing and must not be "simplified" away: an operator record **skips the `topLiked` window cutoff** (a listener like ageing out is a taste snapshot expiring, an operator like ageing out is the DJ forgetting curation the operator set by hand) and **survives the `MAX_RECORDS` trim** (`trimTo` evicts oldest LISTENER records first, falling back to plain oldest-first only when curation alone exceeds the cap, so the bound always holds). Deleting likes never unstars in Navidrome, with ONE deliberate exception: the operator un-hearting when **no likes remain** for the song — that is a toggle, not a purge, and the "none remain" guard is what stops a star earned by twenty listener likes being discarded. Row hearts on every library view read one `GET /likes/index` map rather than per-endpoint annotation, because browse/search/sounds-like come from three different sources and Navidrome search rows have no `library.db` row to annotate. Pinned by `scripts/likes.test.ts`.
- **Blocklist rules** (#1300 FR 1, closes #752): the never-play blocklist carries **rule entries** beside the id entries — attribute predicates (`genre`/`tag`/`mood`/`artist`/`album`/`title`/`playlist` + any-of values) with an optional seasonal **allow-window** (inclusive month/day, wraps year-end, station zone) and an optional show scope — same `blocklist.json`, same routes, same Blocked tab. Pure matching lives in `music/blocklist-rules.ts` (pinned by `scripts/blocklist-rules.test.ts`); `blocklist.ts` owns the evaluation context — a ~15s-memoised active-rule set (clock via `zonedParts`, show via `resolveActiveShow`, both resolved once per sweep, NOT per track) and pre-resolved playlist member sets (the one async input, so `matchOf` stays synchronous). **Enforcement is inherited, not added**: rules ride `hitOf()`/`isBlocked()` inside the existing chokepoints (subsonic reject, library sources, `queue.push` gate, request declines, `annotate`) — never add a second rule-filter at a pick path, that's how the two kinds would drift. `hitOf()` answers entries-FIRST (the UI unblocks exactly the entry), and `BlockRef` is now a `kind: 'entry' | 'rule'` union. Rules are absolute like the id list — no never-starve anywhere, requests included; the row UI deliberately offers **no one-click unblock for a rule ref** (one rule can block hundreds of rows — edits happen on the Blocked tab). `tag` matches EXACT-normalised across every ingested namespace (genres ∪ moods ∪ audioMoods ∪ Last.fm — `show-filter.trackAllTags`); `genre` reuses `genreMatches`' refine direction (blocking "Punk" drops "Punk Rock", not the reverse). Custom file tags (e.g. a country) only work once they land in a field the pipeline ingests — that's an ingestion boundary, not a rules bug.
