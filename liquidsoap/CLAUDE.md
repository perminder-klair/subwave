# CLAUDE.md — `liquidsoap/`

Loaded when working under `liquidsoap/`. The controller↔Liquidsoap file-IPC contract (which file is written by whom, and at what poll interval) stays in the root `CLAUDE.md`. **Every rule about `radio.liq` itself lives here** — the pipeline order below, then the full rationale under *Rules you must not break*.

### Liquidsoap (`liquidsoap/radio.liq`)

Pipeline in order:

1. `dj_queue` (controller-fed `request.queue`) **fallback→** `auto_playlist` (`playlist(reload_mode="watch")`) → base `music`.
2. **`music_meta` captured here**, before the cross — this is what `on_metadata` hooks (the marker-file contract is under **Architecture** in the root `CLAUDE.md`).
3. `rotate(weights=[1, jingle_ratio], [jingles, music])` — one automatic jingle per N tracks, on the **raw pre-cross** music source. Then `jingle_now_queue` wraps that result as a priority fallback, gated off while voice or a bed is live. This order is load-bearing: a manual press must beat both an existing `dj_queue` pick and an automatic jingle that happens to be due, while an unsafe boundary leaves the request queued. The rotate itself must stay here: `rotate` is track_sensitive and only advances at a track boundary of the source it is playing, and everything below presents its output as one never-ending track, so a rotate further down plays one jingle at startup and is then stuck on music forever.
4. `cross(duration=crossfade_duration, dj_transition, music)` — low-level `cross` (not the high-level `crossfade` wrapper, which ignores custom callbacks). `dj_transition` builds `fade.out(d) + fade.in(d)` spanning the **full** cross buffer so tracks curve past each other at ~−6 dB midpoint and sum to ~unity. Earlier per-transition energy scaling caused audible doubling — don't reintroduce it; vary the buffer length instead.
5. **Dead-air guard** — `fallback(id="music_safety", track_sensitive=false, [music, emergency])`, bound to `music` **between steps 4 and 6**. The `emergency` single is what the broadcast pulls when the music chain dies. It must sit ABOVE **every `add` in the music path** — the studio bed (step 6) and the ducking layers (step 7) — because `add` is ready if ANY input is: `smooth_add` gives its `special` input a `blank()` fallthrough, and the bed leg is `mksafe(single(...))`, i.e. infallible. Either one makes the bus permanently ready, so a fallback below it can never select its second branch (#1300 bug 7 — measured -91.0 dB of silence with it under the ducking, and with the bed ON the guard bound to `music_bus` never fired at all, airing the bed alone at -57.1 dB versus -9.0 dB for the loop with the guard bound to `music`). It stays BELOW `music_meta` and the rotate so now-playing metadata and jingle counting are untouched. The emergency branch **fades in over ~1s** (two fades — the child's own one-shot `fade.in` for the cold boot, which `switch` gives no transition, plus a `transitions=` entry for every later switch); the music branch keeps the identity transition so recovery is instant. That fade is **not a debounce** — the guard still fires immediately; only its level ramps. See *Rules you must not break* below; do not add a decorative second guard further down. **No `blank.skip`**: it was removed (#660) because it busy-loops at ~100% CPU whenever the music chain is empty (fresh install, Navidrome down, playlist exhausted), pegging a core and starving Icecast (`/stream.mp3` 404s). The spin happens in any position, so don't reintroduce it to skip silence — the emergency fallback already covers a dead source.
6. **Studio bed** — `/sounds/bed.mp3` at weight `0.02`, mixed in before voice ducking so `smooth_add` ducks it with the music. Currently **off** (`bed_enabled = false` in `radio.liq`): the looping ambient bed was audible under the DJ's voice during links. Re-enabling is a source edit, not a setting — and it is only safe because the guard (step 5) sits ABOVE this `add`.
7. **Two stacked `smooth_add` ducking layers** — `voice_queue` (heavy, p=0.22) then `intro_queue` (light, p=0.30), plus an `sfx_queue` layer on top. Gated talkbax-style, NOT RMS-keyed: an earlier RMS sidechain follower drove `music_bus` to −91 dB even with the voice queue empty (git `f38a9af`). Both voice channels pass through `mic_chain` (compress → makeup gain). HPF/presence shelf skipped — this build hits "Early computation of source content-type" on IIR filters fed by `request.queue`.
8. **Broadcast bus** — brick-wall limiter (20:1 at −1 dBFS) only. Normaliser/widener/bus-compressor were all removed (they reshaped the masters). The limiter is a safety net for MP3 inter-sample peaks; typically 0 dB of reduction on catalogue audio.
9. **Parallel Icecast outputs** (`make_stream_outputs()`, wrapped in one `stream_on`/`stream_off`): `%mp3` → `/stream.mp3` (**always served** — universal floor); when enabled, `%opus(48kHz)` → `/stream.opus`; `%ogg(%flac(44.1kHz, 16-bit))` → `/stream.flac` (lossless); and `%fdkaac(aac-lc, adts, 44.1kHz)` → `/stream.aac` (served `audio/aac`). Opus/FLAC/AAC are each gated on their own `liquidsoap_*_enabled.txt` (**all off by default**; opt in via admin → Settings, mirroring the `archive_enabled` pattern — only an explicit `"true"` enables it). MP3/Opus/AAC bitrates are operator-configurable from fixed sets (`stream_bitrate` / `opus_bitrate` / `aac_bitrate`); each encoder needs a **parse-time literal** bitrate, so radio.liq pre-bakes one `if/elsif` branch per value (keep in sync with `MP3_BITRATES` / `OPUS_BITRATES` / `AAC_BITRATES` in `settings.ts`). When an optional mount is off, that output isn't created (no encoder; Opus also skips its 44.1→48k resample). FLAC stays at the source 44.1kHz (no resample) and is a *lossless capture of the processed bus* — only a true lossless tier when the source files are themselves lossless. FLAC and AAC are intended for external players (the web/native players don't auto-select them; the web player only ever upgrades to Opus). All mounts share the same `radio` bus. Plus `output.file(%mp3(128), reopen_when={0m0s}, "/var/sub-wave/archive/%Y-%m-%d/%H-00.mp3")` for MP3-only hourly archives.

Also: a custom `subhttp:` protocol shells out to `curl` (Liquidsoap's `http.get.stream` returns spurious 522s on the Cloudflare-fronted Navidrome origin). Telnet server on port 1234 (reachable as `broadcast:1234`) exposes the custom `restart` command.

## Rules you must not break

Each of these records a measured failure. The one-line version is in the root
`CLAUDE.md`; the reasoning is here.

- **`radio.liq` `on_metadata`**: keep it on `music_meta`, the pre-cross handle (post-cross fires twice; `on_track` gets swallowed by source switches). Step 2 above, and **Architecture** in the root `CLAUDE.md`.
- **Nothing inside a `thread.run` callback may raise.** An uncaught exception kills that thread **permanently**, freezing the dead-air guard at whatever it last latched — worst case the emergency loop forever with no path back. This is why `write_starve_marker` wraps its `file.write` in `try`/`catch` and logs instead: reporting must not share a failure domain with the guard it reports on. Observed in development as an `EACCES` that killed the tick outright, and the realistic trigger is the same unwritable state mount `ensure_tmp_dir` defends against.
- **On-demand jingle priority and metadata isolation**: `jingle_now_queue` must wrap the automatic rotate and base music as the first source in a track-sensitive fallback. Putting it inside the rotate lets a due automatic jingle win; putting it in `dj_queue` puts it behind already-sent tracks. Its `source.available` gate must keep both `not bed_on_air()` and `time() > voice_until()` — manual means never drop the press, not "talk over the DJ" or "split a bed pair". Its own `on_metadata` writes `jingle-playing.json` through `jingle_now_tmp_dir`; the source stays outside `music_meta`, so an uploaded clip's retained ID3 tags can never reach `now-playing.json` or the ICY title. The automatic rotate's own gate must carry `not jingle_now_on_air()` for the mirror-image reason — otherwise it stacks a stinger on top of an announcement an operator fired by hand — and **every** `on_meta` branch must clear that ref, or it latches true and starves the rotate permanently (the `bed_on_air` failure, repeated). Pinned by `controller/scripts/jingle-play.test.ts`.
- **A jingle marker carries its own measured length.** Both writers of `jingle-playing.json` stamp `durationSec` via `jingle_duration` (`request.duration`, wrapped in a try/catch that degrades to `0.` = unmeasured). Do not drop it back to `{filename, startedAt}`: the controller's collision guard can only parse a **RIFF** header (`wavDurationMs`), and `jingles.importAudio` stores an upload **verbatim in its original container** when the host has no ffmpeg — so an `.mp3` announcement fell back to a blind 15s guess and the DJ talked over the rest of it. Liquidsoap can measure anything it can decode, so it is the only side that can answer this. Unlike `voice_marker`, the duration cannot be computed *after* the marker (it is part of the payload), which is what makes that try/catch load-bearing rather than decorative.
- **`radio.liq` atomic marker writes (#1240)**: **every** `file.write(atomic=true)` MUST carry a `temp_dir=` on the state fs — no exceptions, and a new marker file means a new `ensure_tmp_dir` line (there are seven writers today: now-playing, jingle, jingle-now, bed, starve, voice, intro; don't rely on that count, grep `ensure_tmp_dir`) (`ensure_tmp_dir` at the top of the file, one dir per writer). Without it Liquidsoap picks a temp dir under `$TMPDIR`, which on Docker is the container overlay while the state dir is a bind mount: the rename is cross-device, the stdlib logs `Atomic rename failed` and silently degrades to a NON-atomic copy — i.e. the half-written-JSON race `atomic=true` exists to prevent was never actually prevented on any Docker install. One temp dir **per writer**, not per marker FILE, because the stdlib always names the temp file `atomic.write` inside the dir it is given and the jingle write is `synchronous=false` — `jingle-playing.json` has two writers (the automatic rotate's `on_metadata` and `jingle_now_queue`'s hook) and `jingle_tmp_dir`/`jingle_now_tmp_dir` is why they don't tear each other, exactly as `voice_tmp_dir`/`intro_tmp_dir` do for the voice channels. `ensure_tmp_dir` probe-writes and returns `null` on failure (`file.mkdir` does NOT raise), so an unwritable state mount degrades to the old behaviour instead of raising inside `on_metadata`.
- **`radio.liq` emergency dead-air fallback position (#1300 bug 7)**: `fallback(id="music_safety", track_sensitive=false, [music, emergency])` MUST stay **above every `add` in the music path** — both the `smooth_add` ducking layers AND the studio-bed mix. It binds to `music`, immediately BEFORE the `bed_enabled` if/else. Anything below an `add` can never fire, because `add` is ready if ANY input is: the stdlib builds smooth_add as `add(normalize=false, [normal, fallback(track_sensitive=false, [special, blank()])])`, that inner fallback falls through to `blank()` so it is ALWAYS ready, and the bed leg is `mksafe(single(bed))` — `mksafe` makes it INFALLIBLE. Either way the bus reports ready with the music chain starved and a fallback under it selects index 0 forever. The guard lived at the BOTTOM of the chain for its whole life and was dead code the entire time; nobody noticed because the failure it guards against also needs the jingle rotate silenced, and the rotate had been masking every starve (that's bug 7 itself). Gating jingles off without moving this turns "stingers forever" into digital silence forever — measured -91.0 dB at the output, versus -3.0 dB with the fallback in its correct position. The bed trap is the same bug re-armed by a **documented** one-line source edit (`bed_enabled = true`, "flip back to `true` to restore it"): measured on the full chain with the bed on, the guard bound to `music_bus` never selected `emergency` at all and the output was the bed alone at -57.1 dB, versus -9.0 dB (the loop, at its own level) with the guard bound to `music`. **Do not leave a second one at the bottom** "for safety": a fallback that looks like a dead-air guard but structurally cannot fire is what caused this. Position also matters upward — it stays BELOW `music_meta` and the jingle rotate so now-playing metadata and jingle counting are untouched. A harness that tests this guard MUST build the duck layers (and, for the bed claim, the bed `add`); one that runs `output.dummy` on the bare rotate proves nothing (that is exactly how the false claim got shipped).
- **`radio.liq` emergency fade-in — not a debounce (#1300 bug 7)**: the guard's emergency branch ramps up over `EMERGENCY_FADE_SEC` (1.0s). `track_sensitive=false` makes it switch the instant `music` reports not-ready, and now that it can actually fire it also fires on brief real gaps — cold boot before `auto.m3u` resolves, and track seams where `dj_queue` and `auto_playlist` are momentarily both unready (auto entries are whole-file `subhttp:` downloads, so a slow Navidrome widens the window). **Never "fix" that by delaying the switch**: a dead-air guard that waits before firing is a guard that doesn't fire, which is the exact bug class above. Fire immediately, ramp the LEVEL — a sub-second stab is inaudible, a real starve is at full level in ~1s, timing untouched. It takes **two** fades and both must stay: `switch` applies no transition to its FIRST selection (measured — `Switch to emergency.` at boot vs `…with transition.` after), and boot IS that first selection, so `emergency` carries its own one-shot `fade.in` (default `track_sensitive=false` memoises the ramp to the source's first frame ever — right for boot, useless later, since a looping single never reaches a fresh track boundary); the `transitions=` entry then ramps every later switch. The music branch keeps the stdlib identity transition — coming BACK must be instant, or a recovered station fades up over its own first second of music. `fade.in` returns extra methods, so both sites cast `(… : source)` to unify with the plain `music` child. Measured (100ms RMS): boot -38.5 → -9.0 dB over 1.0s, mid-run -32.6 → -9.0 dB over 1.0s, recovery a single-window step with no ramp, unchanged after 43 switches in one process.
- **`proto_subhttp` must never judge a download by curl's exit code alone (#1405)**: the Subsonic API carries its error code INSIDE the body, so Navidrome answers a missing file with **HTTP 200** and a JSON `subsonic-response` blob. `--fail` cannot see that — the status is 200 — and the old "exit 0 + non-empty file" test handed the error page to the decoders, which logged the useless `Available decoders cannot decode "/tmp/liq-curl-….mp3"`. The request then failed to resolve, Liquidsoap dropped it, and the station coasted on the unfiltered auto playlist while the controller's pick sat `sent:true` for ~3 more tracks. What identifies it is the **content type**, so the protocol asks curl (`-w '%{http_code} %{content_type}'`) and refuses json/xml/text bodies, sub-4 KiB files, and non-2xx statuses, each with its own operator-facing log line. A controller handoff carries a one-use probe id in the URL fragment; the protocol records `ready` only after those checks and `failed` on every rejection, and the controller consumes that exact outcome over `subhttp_probe_status`. **Never substitute `dj_queue.queue()` membership for this signal**: idle/resolving requests are visible there, while healthy boundary-prefetch downloads are not. Missing/unknown outcomes fail open. Stream query strings are auth-bearing and must be redacted in every log. Verified against a fake origin: 200+JSON reports `failed`, real audio reports `ready`, each result is consumed once, and the logs contain no query credentials.
- **Crossfade**: keep fade duration equal to the cross buffer (`d = crossfade_duration()`, `fade.out(d)` / `fade.in(d)`). Shorter fades inside a fixed buffer let the outgoing track play full while the incoming ramps, summing to +6 dB (audible doubling). Vary the buffer length instead.
- **Loop transition level**: capture the outgoing bar from the raw `a.source`, then apply the linear `loop_gain = 1 - elapsed/d` **after** the comb cascade so the repeated bar gives up headroom as the new track rises. The cascade uses `feedback=0.0` (a 0 dB delayed copy) and power-of-two delays, so its one-bar input lands in non-overlapping bar slots at unity — **never apply global makeup to the cascade**. It doubles the direct capture pass before any delayed tap exists and recreates the measured ~+6 dB entry jump. Do not put Loop back on the logarithmic outgoing fade or restore its old flat-until-late master; keep `scripts/fx-render-test.sh loopcheck` within 1 dB and the harness implementation in lockstep with `radio.liq`.
- **Ducking**: stick with `smooth_add`. An RMS sidechain follower drove `music_bus` to silence (`f38a9af`). `smooth_add` is gated talkbax — it cares only whether the channel has signal, not how loud.
