### Native app (`app/`)

A separate **Expo SDK 56 / React Native** project (own `package.json`, `node_modules`, `eas.json`) — the native iOS + Android player. It ports the web player's hooks/UI to RN + NativeWind, with the same listener experience (now-playing, booth, timeline, requests, schedule, themes, a Skia visualiser). Background audio + lock-screen / CarPlay / Android Auto controls come from **`react-native-track-player`** (wrapped in `src/audio/player.ts` so it's swappable). Like the web player, it's a player for *any* station: the base URL is fully runtime (`StationContext` → `createApi(baseUrl)`), defaulting to the public station, and listeners can add stations by address. Stream defaults to the MP3 floor (`/stream.mp3`); listeners can pick the optional Opus/FLAC/AAC mounts per station via the back panel's SIGNAL row (`lib/streamFormat.ts` gates the choice on the `/now-playing` `stream` flags AND platform decodability — iOS AVPlayer can't demux Ogg, so Opus/FLAC are Android-only; Cast stays MP3). `service.ts` wires remote Play/Pause/Stop but **not skip** (shared live stream).

Architecture-critical and easy to break — read [`app/docs/TESTING.md`](app/docs/TESTING.md) before touching native config:

- **New Architecture is mandatory** (RN 0.85 ignores `newArchEnabled=false`). Reanimated 4 requires it. **RNTP is the lovegaoshi fork, pinned by commit** (`github:lovegaoshi/react-native-track-player#<sha>` — Apache-2.0, Media3 `MediaLibraryService` inside, same v4 JS API, carries its own new-arch fix so the old patch-package patch is gone; the git-dep `prepare` builds with **yarn**, which must exist on the machine/builder). It's what makes Android Auto possible at all: stock RNTP v4 can't expose a browsable media service (upstream won't-fix; v5 fixed it but went commercial, €999/yr).
- **Car integration (`src/car/`)**: `browseTree.ts` (station list as data → `setBrowseTree` for Android Auto), `carTune.ts` (tune-from-car path, callable from the headless service; `usePlayer` adopts a car-initiated switch via the `streamBelongsTo` guard instead of stopping it), `carPlay.ts` (CarPlay `ListTemplate` → shared tune path → system Now Playing). Native halves come from `plugins/withAndroidAuto.js` + `plugins/withCarPlay.js` on prebuild. **Two ship gates, both env-controlled in `eas.json`**: the CarPlay entitlement is stripped from device builds until Apple grants it (`SUBWAVE_NO_CARPLAY_ENTITLEMENT=1`), and the Android Auto declaration is stripped from Play `production` builds (`SUBWAVE_NO_ANDROID_AUTO=1`) because Google Play **enforced against it on 20 Jun 2026** ("media apps that use TTS engine readout for content are not permitted") — see `docs/TESTING.md` before touching either gate.
- **`ios/` and `android/` are gitignored** (Continuous Native Generation) — regenerated from `app.json` + `assets/` by `expo prebuild` / EAS. The source of truth for icons/splash is `assets/` (disc-mark branding) + `app.json`.

Distribution is **EAS cloud builds** → iOS TestFlight + Android internal-distribution link (project `@pinku1/subwave`, bundle `com.getsubwave.app`). The repeat-release workflow lives in the `subwave-app-ios-release` and `subwave-app-android-release` skills; getting it onto a physical Android phone over USB is `subwave-app-android`. See `app/README.md`.
